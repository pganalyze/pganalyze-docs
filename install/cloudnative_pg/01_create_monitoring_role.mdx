[CloudNativePG](https://cloudnative-pg.io/) (CNPG) lets you manage Postgres roles declaratively
through the `Cluster` resource, instead of connecting and running `CREATE USER` yourself. We
recommend using this to create a dedicated monitoring role for pganalyze.

## Create a Secret for the role's password

Unlike most declarative role management in CNPG (and unlike the SQL-based monitoring user setup
used for other platforms in these docs), CNPG does **not** generate a password for you when you
declare a role in the `Cluster` spec. You need to create a Kubernetes `Secret` with the
credentials yourself, and reference it from the role.

We've generated a random password for you below, but you can replace it with one of your choosing:

Apply it with `kubectl apply -f pganalyze-monitoring-secret.yaml`, or create it inline:

## Declare the role on your Cluster

Add the role to `.spec.managed.roles` in your `Cluster` manifest, referencing the Secret you just
created, and granting it the built-in `pg_monitor` role (which covers most of what the collector
needs to read):

```yaml
apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: my-cluster
spec:
  managed:
    roles:
      - name: pganalyze
        ensure: present
        login: true
        connectionLimit: 5
        inRoles:
          - pg_monitor
        passwordSecret:
          name: pganalyze-monitoring-user
```

Apply this change with `kubectl apply -f cluster.yaml`. CNPG's operator picks it up and creates the
role on the primary automatically. No restart is needed for a role change like this.

## Add helper functions for column and extended statistics

`pg_monitor` covers query and activity statistics, but pganalyze also collects some additional
column and extended statistics through a small set of `SECURITY DEFINER` helper functions, which
still need to be created with plain SQL as a superuser. The easiest way to get a superuser SQL
prompt against a CNPG cluster is the [`cnpg` kubectl plugin](https://cloudnative-pg.io/documentation/current/kubectl-plugin/):

```bash
kubectl cnpg psql my-cluster
```

This connects you directly to the primary as the `postgres` superuser over a local socket inside
the pod, so it works even if you haven't enabled network-level superuser access for the cluster.
Once connected, run the following for each database you want to monitor. Most CNPG clusters only
have one application database, and unless you customized `.spec.bootstrap.initdb.database` when
creating the cluster, its name defaults to `app`:

## Verify connection

CNPG creates a `<cluster-name>-rw` Service that always points at the current primary. That's what
the collector should connect to. To verify the role can connect from outside the cluster, forward a
local port to it:

```bash
kubectl port-forward svc/my-cluster-rw 5432:5432
```

Then, in another terminal:

<VerifyConnection host="localhost" />

Write down the username and password of the monitoring role, we'll use it in Step 4 of this guide.
